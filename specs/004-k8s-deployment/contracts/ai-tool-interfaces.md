**Feature**: 004-k8s-deployment

**Purpose**: Define interfaces for interacting with AI deployment tools

## Overview

This document specifies the interfaces for AI tools used in Phase IV deployment. Each tool has a defined input/output contract that ensures consistent, auditable interactions.

## Docker AI (Gordon) Interface

### Generate Dockerfile

**Purpose**: Generate production-ready Dockerfile for application component

**Input**:
```yaml
tool: docker-ai
action: generate-dockerfile
parameters:
  component: string              # "backend" or "frontend"
  base_image: string             # e.g., "python:3.11-alpine"
  application_type: string       # e.g., "fastapi", "react-spa"
  dependencies_file: string      # Path to requirements.txt or package.json
  entry_point: string            # Application entry command
  port: integer                  # Application port
  health_check_path: string      # Health check endpoint
  optimization_level: string     # "development" or "production"
```

**Output**:
```yaml
status: string                   # "success" or "error"
dockerfile_content: string       # Generated Dockerfile content
metadata:
  estimated_size: string         # e.g., "180MB"
  build_stages: integer          # Number of build stages
  security_score: string         # "high", "medium", "low"
  recommendations: array         # List of optimization suggestions
error_message: string            # Present if status is "error"
```

**Example Prompt**:
```
Generate a production-ready Dockerfile for a Python 3.11 FastAPI backend application.

Requirements:
- Base image: python:3.11-alpine
- Dependencies: requirements.txt in ./backend directory
- Entry point: uvicorn main:app --host 0.0.0.0 --port 8000
- Health check: GET /health endpoint
- Optimization: Multi-stage build, minimize image size
- Security: Run as non-root user, no secrets in layers

Output the complete Dockerfile content.
```

**Expected Response Format**:
```dockerfile
# Stage 1: Builder
FROM python:3.11-alpine AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Stage 2: Runtime
FROM python:3.11-alpine
WORKDIR /app
RUN adduser -D -u 1000 appuser
COPY --from=builder /usr/local/lib/python3.11/site-packages /usr/local/lib/python3.11/site-packages
COPY . .
USER appuser
EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:8000/health || exit 1
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Validation**:
- Dockerfile must be valid syntax
- Must include HEALTHCHECK instruction
- Must run as non-root user
- Must use multi-stage build for production

**Audit Trail**:
- Prompt saved to: `deployment/docs/ai-prompts/YYYY-MM-DD-HH-MM-SS-docker-ai-[component]-dockerfile.md`
- Generated Dockerfile saved to: `deployment/dockerfiles/[component].Dockerfile`
- Commit with message: `feat(deploy): add [component] Dockerfile generated by Docker AI`

## kubectl-ai Interface

### Deploy Application

**Purpose**: Deploy application to Kubernetes cluster using Helm

**Input**:
```yaml
tool: kubectl-ai
action: deploy
parameters:
  chart_path: string             # Path to Helm chart directory
  release_name: string           # Helm release name
  namespace: string              # Kubernetes namespace
  values: object                 # Configuration overrides
    backend:
      replicas: integer
      image:
        tag: string
    frontend:
      replicas: integer
      image:
        tag: string
  wait: boolean                  # Wait for deployment to complete
  timeout: string                # Timeout duration (e.g., "5m")
```

**Output**:
```yaml
status: string                   # "success" or "error"
release_info:
  name: string
  namespace: string
  revision: integer
  status: string                 # "deployed", "failed", etc.
  chart_version: string
  app_version: string
resources_created:
  - kind: string                 # "Deployment", "Service", etc.
    name: string
    status: string
deployment_time: string          # Duration in seconds
error_message: string            # Present if status is "error"
```

**Example Prompt**:
```
Deploy the todo-chatbot Helm chart to the default namespace with the following configuration:
- Release name: todo-chatbot
- Backend replicas: 3
- Backend image: todo-backend:v1.0.0
- Frontend replicas: 1
- Frontend image: todo-frontend:v1.0.0
- Wait for all pods to be ready (timeout: 5 minutes)

Use the Helm chart located at: deployment/helm/todo-chatbot/
```

**Expected Command**:
```bash
helm install todo-chatbot deployment/helm/todo-chatbot/ \
  --namespace default \
  --set backend.replicas=3 \
  --set backend.image.tag=v1.0.0 \
  --set frontend.replicas=1 \
  --set frontend.image.tag=v1.0.0 \
  --wait \
  --timeout 5m
```

**Validation**:
- All pods must reach "Running" state
- All containers must pass readiness probes
- Services must have endpoints assigned
- Deployment must complete within timeout

**Audit Trail**:
- Prompt saved to: `deployment/docs/ai-prompts/YYYY-MM-DD-HH-MM-SS-kubectl-ai-deploy.md`
- Command and output logged to: `deployment/docs/deployment-log.md`
- Commit with message: `deploy: release todo-chatbot v[version] via kubectl-ai`

### Scale Application

**Purpose**: Scale application components horizontally

**Input**:
```yaml
tool: kubectl-ai
action: scale
parameters:
  release_name: string           # Helm release name
  component: string              # "backend" or "frontend"
  replicas: integer              # Target replica count
  namespace: string              # Kubernetes namespace
```

**Output**:
```yaml
status: string                   # "success" or "error"
scaling_info:
  component: string
  previous_replicas: integer
  current_replicas: integer
  ready_replicas: integer
scaling_time: string             # Duration in seconds
error_message: string            # Present if status is "error"
```

**Example Prompt**:
```
Scale the backend component of the todo-chatbot deployment to 5 replicas in the default namespace.
```

**Expected Command**:
```bash
kubectl scale deployment/todo-chatbot-backend --replicas=5 --namespace=default
```

**Validation**:
- Deployment must update replica count
- New pods must reach "Running" state
- All pods must pass readiness probes

**Audit Trail**:
- Prompt saved to: `deployment/docs/ai-prompts/YYYY-MM-DD-HH-MM-SS-kubectl-ai-scale.md`
- Event logged to: `deployment/docs/deployment-log.md`

### Rollback Deployment

**Purpose**: Rollback to previous deployment version

**Input**:
```yaml
tool: kubectl-ai
action: rollback
parameters:
  release_name: string           # Helm release name
  revision: integer              # Target revision (optional, defaults to previous)
  namespace: string              # Kubernetes namespace
  wait: boolean                  # Wait for rollback to complete
```

**Output**:
```yaml
status: string                   # "success" or "error"
rollback_info:
  from_revision: integer
  to_revision: integer
  chart_version: string
  app_version: string
rollback_time: string            # Duration in seconds
error_message: string            # Present if status is "error"
```

**Example Prompt**:
```
Rollback the todo-chatbot deployment to the previous revision in the default namespace. Wait for all pods to be ready.
```

**Expected Command**:
```bash
helm rollback todo-chatbot --namespace=default --wait
```

**Validation**:
- Helm release must revert to target revision
- All pods must reach "Running" state
- Application must pass health checks

**Audit Trail**:
- Prompt saved to: `deployment/docs/ai-prompts/YYYY-MM-DD-HH-MM-SS-kubectl-ai-rollback.md`
- Event logged to: `deployment/docs/deployment-log.md`

## kagent Interface

### Check Deployment Health

**Purpose**: Analyze cluster state and validate deployment health

**Input**:
```yaml
tool: kagent
action: check-health
parameters:
  release_name: string           # Helm release name
  namespace: string              # Kubernetes namespace
  components: array              # List of components to check
```

**Output**:
```yaml
status: string                   # "healthy", "degraded", "unhealthy"
overall_health:
  total_pods: integer
  running_pods: integer
  pending_pods: integer
  failed_pods: integer
component_health:
  - name: string                 # Component name
    status: string               # "healthy", "degraded", "unhealthy"
    replicas:
      desired: integer
      current: integer
      ready: integer
    issues: array                # List of identified issues
service_health:
  - name: string                 # Service name
    type: string                 # Service type
    endpoints: integer           # Number of endpoints
    status: string               # "active", "unavailable"
recommendations: array           # Actionable recommendations
error_message: string            # Present if analysis fails
```

**Example Prompt**:
```
Check the health of the todo-chatbot deployment in the default namespace. Analyze all components (backend, frontend) and their services. Provide recommendations if any issues are detected.
```

**Expected Analysis**:
```yaml
status: healthy
overall_health:
  total_pods: 4
  running_pods: 4
  pending_pods: 0
  failed_pods: 0
component_health:
  - name: backend
    status: healthy
    replicas:
      desired: 3
      current: 3
      ready: 3
    issues: []
  - name: frontend
    status: healthy
    replicas:
      desired: 1
      current: 1
      ready: 1
    issues: []
service_health:
  - name: todo-backend
    type: ClusterIP
    endpoints: 3
    status: active
  - name: todo-frontend
    type: NodePort
    endpoints: 1
    status: active
recommendations: []
```

**Validation**:
- All pods must be analyzed
- Service endpoint counts must match ready replicas
- Issues must be specific and actionable

**Audit Trail**:
- Prompt saved to: `deployment/docs/ai-prompts/YYYY-MM-DD-HH-MM-SS-kagent-health-check.md`
- Health report logged to: `deployment/docs/deployment-log.md`

### Diagnose Failure

**Purpose**: Analyze failed deployment and provide root cause analysis

**Input**:
```yaml
tool: kagent
action: diagnose-failure
parameters:
  release_name: string           # Helm release name
  namespace: string              # Kubernetes namespace
  failure_type: string           # "deployment", "pod", "service"
  resource_name: string          # Specific resource to diagnose
```

**Output**:
```yaml
status: string                   # "diagnosed" or "unknown"
root_cause:
  category: string               # "image", "resource", "configuration", "network"
  description: string            # Detailed explanation
  evidence: array                # Supporting evidence (logs, events)
recommended_actions:
  - action: string               # What to do
    priority: string             # "critical", "high", "medium", "low"
    command: string              # Suggested command (if applicable)
related_issues: array            # Other issues that may be related
error_message: string            # Present if diagnosis fails
```

**Example Prompt**:
```
Diagnose why the todo-chatbot-backend deployment failed in the default namespace. Analyze pod events, container logs, and resource constraints. Provide root cause and recommended actions.
```

**Expected Diagnosis**:
```yaml
status: diagnosed
root_cause:
  category: image
  description: "Container image 'todo-backend:v1.0.0' not found in local registry"
  evidence:
    - "Pod event: Failed to pull image 'todo-backend:v1.0.0': image not found"
    - "ImagePullBackOff status on all backend pods"
recommended_actions:
  - action: "Build the backend image using Docker AI-generated Dockerfile"
    priority: critical
    command: "docker build -t todo-backend:v1.0.0 -f deployment/dockerfiles/backend.Dockerfile ./backend"
  - action: "Verify image exists in Minikube's Docker daemon"
    priority: high
    command: "eval $(minikube docker-env) && docker images | grep todo-backend"
related_issues: []
```

**Validation**:
- Root cause must be specific and evidence-based
- Recommended actions must be actionable
- Commands must be valid and safe to execute

**Audit Trail**:
- Prompt saved to: `deployment/docs/ai-prompts/YYYY-MM-DD-HH-MM-SS-kagent-diagnose-failure.md`
- Diagnosis logged to: `deployment/docs/deployment-log.md`

## Interface Compliance

All AI tool interactions must follow these principles:

1. **Prompt Recording**: Every prompt must be saved with timestamp and tool name
2. **Output Validation**: All outputs must be validated against expected schema
3. **Error Handling**: Errors must be captured and logged with context
4. **Auditability**: All interactions must be traceable to Git commits
5. **Human Review**: Generated artifacts must be reviewed before execution

## Testing Contracts

Each interface should be tested with:
- Valid inputs (happy path)
- Invalid inputs (error handling)
- Edge cases (resource limits, timeouts)
- Failure scenarios (network issues, tool unavailability)

Test results should be documented in the deployment log for continuous improvement of AI prompts.
